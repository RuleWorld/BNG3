# SBML package decisions

Core, Multi and comp are decided release requirements. The package dispositions below are decided by `DECISIONS.md` item 12. This review uses the [official Level 3 package catalogue](https://sbml.org/documents/specifications/level-3/), [Core L3V2R2](https://sbml.org/documents/specifications/level-3/version-2/core/), [Multi V1R2](https://sbml.org/specifications/sbml-level-3/version-1/multi/sbml-multi-version-1-release-2.pdf), and [comp V1R3](https://sbml.org/documents/specifications/level-3/version-1/comp/). Some summary pages have stale version labels; the linked specification release is the normative version.

“Representable” below distinguishes exact kinetic semantics from lossless descriptive metadata. Preserving a diagram or annotation does not turn it into a simulated reaction. These are decided dispositions derived from the specifications, not claims that BNG3 already implements them.

| Package | Exact BNGL/BNG3 representation | Decision and work | Independent acceptance |
|---|---|---|---|
| Core | Ordinary reactions map to rules; general events, delay/history, algebraic constraints, dynamic stoichiometry and fast-reaction constraints require corresponding native semantics, not static mass-action substitution | **Import, decided.** Complete Core semantics in the compiled model and backends, extending BNGL/BNGIR where necessary. Preserve source units, scopes, initialization, constraints and protocol. L3V1 fast semantics are included although L3V2 removed that attribute. | Official SSTS expected outputs, independent source execution and analytic DDE/DAE/fast-equilibrium examples. |
| multi | Typed components, internal states, bonds, pattern predicates, location and component mapping fit rule-based models; all cardinality and compartment constraints must be explicit | **Import, decided.** Complete every construct in the inventory, including structural products and intra-species reactions. | Independent explicit-species expansion, canonical BNG2/native NFsim, libSBML structural validation. |
| comp | Hierarchical models can be flattened with exact identifier scope, replacements, deletions and time/extent conversion factors | **Import, decided.** Complete deterministic source resolution and provenance, then flatten while preserving mathematics. External definitions and nested references are release work. | Compare independent libSBML and JSBML flattening, then execute the flattened source with an independent solver. |
| fbc | Flux bounds and optimization objectives do not define a kinetic stochastic process | **Do not import, decided.** Detect fbc and explain that a kinetic model is required; do not invent reaction rates from a flux optimum. | Independently authored fbc documents produce the documented diagnostic, never nominal kinetic success. |
| distrib | Distribution/uncertainty metadata can be retained; random draws require explicit draw timing, dependence and RNG semantics beyond a deterministic BNGL expression | **Import, decided.** Preserve uncertainty metadata and implement exact distribution sampling semantics in compiled expressions/protocol. Retain distribution identity and parameters in BNGIR. This requires implementation, not substitution with a mean. | Analytic distribution laws, independence/correlation checks and specification examples; tests distinguish per-event from per-evaluation draws. |
| arrays | Finite declared arrays with defined dimensions and index rules can expand exactly into scalar symbols/rules; dynamic/symbolic size and indexing need explicit semantics | **Import, decided.** Implement finite expansion and dynamic indexing/size semantics as specified; preserve dimensions and indexing metadata. No guessed truncation. | Independent scalar expansion with exact index/shape checks and identical simulation; draft-version mismatch must be visible. |
| dyn | Creation/destruction resembles rule-based graph edits, but general dynamic entities and topology may exceed molecule creation | **Import, decided.** Map entities and dynamic topology to explicit compiled operations and implement semantics not covered by molecule rules. | Specification examples plus independently implemented transition relations; distinguish entity deletion from zero concentration. |
| qual | Logical transition levels and update policies do not specify mass-action rates or the same CTMC | **Do not import, decided.** Explain that qualitative transitions require a qualitative-model simulator; never invent rates or timing. Retain source metadata only if a user explicitly requests a document-preservation operation. | Source qualitative examples trigger a specific semantic diagnostic; tests ensure no arbitrary rates appear. |
| spatial | Geometries, coordinate fields, diffusion/advection and boundary conditions are not exactly represented by well-mixed compartments | **Do not import, decided.** A spatial PDE/particle engine with spatial state and exact source semantics would be a distinct capability decision; compartment discretization is an approximation and cannot be called exact import. | Known spatial documents receive precise diagnostics; geometrical metadata is never reported as spatial execution. |
| layout | Graphical layout is descriptive and can be represented as metadata attached to stable model IDs | **Import, decided; preserve as metadata.** Retain glyphs, curves, dimensions, positions and object references in BNGIR and export. | libSBML read/write and independent structural metadata comparison; kinetic results remain invariant. |
| render | Graphical styles can be represented as metadata, separate from mathematical state | **Import, decided; preserve as metadata.** Keep colors, gradients, line endings, text/style inheritance and references. | libSBML validation and independent render metadata round trips; no kinetic changes. |
| groups | Group membership and classification can be preserved by ID-reference metadata | **Import, decided; preserve as metadata.** Keep collection/classification/partonomy kind, nesting and member metadata. | Specification examples, reference resolution and exact group round trips. |
| math (extended MathML) | No stable completed package specification in the official catalogue; representability depends on the concrete operators and domains | **Recommend no package import claim until a normative target exists.** Continue implementing all Core MathML now; identify future operators by explicit semantics before adopting a package. | Namespace/version diagnostics and complete Core MathML checks. |

The decisions for distrib, arrays and dyn add concrete implementation obligations. They do not authorize partial support to be advertised as full package support. The package catalogue describes arrays/dyn as drafts and math as not started; Core/Multi/comp are stable targets.

## Current implementation evidence

At `918a5fb1`, `python/bionetgen/atomizer/modern/parser.py:666` implements comp flattening, with inline and source-relative external helpers earlier in that file. `modern/fast_reactions.py:80` implements fast-reaction lowering. `modern/multi.py` contains structural Multi lowering. `modern/events.py` and `tests/python/test_native_events.py` demonstrate existing event machinery. These implementations will be extended and tested against every inventory construct; blanket claims that these families are absent are stale.

The policy does not require mathematically undefined SBML to acquire invented dynamics. Invalid source documents, underdetermined equations and oracle integration failures receive explicit diagnoses. Every valid required construct receives an exact implementation and an independent check.
