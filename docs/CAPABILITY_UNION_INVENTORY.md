## Policy vocabulary proposed for review

- **supported** — public support is limited to the exact listed behavior and its passing acceptance gate. It does not imply the rest of that source feature family is supported.
- **experimental** — the path is opt-in or explicitly provisional, has a bounded contract, and is excluded from general support claims until its gate passes.
- **compatibility-only** — retained to preserve a named legacy interface or interchange behavior; it is not the preferred surface for new development. Any removal still needs an approved migration and release plan.
- **deprecated** — maintainers have approved a replacement, migration guidance, and a removal window. A warning in code alone does not supply a release date.
- **out-of-scope** — maintainers deliberately exclude the named behavior from a named product boundary; the exclusion must be explicit and fail closed where inputs can request it.

The proposed classification column uses these labels only when the evidence supports a bounded recommendation. Where it says **decision required**, maintainers must choose a category; the worksheet does not turn missing implementation into an out-of-scope decision. Proposed owner fields name a review role only. No individual is assigned; maintainer allocation is required.
