# SBML Atomizer scope and completion audit

This audit records the representable scope and the remaining evidence boundary for the SBML Atomizer. It separates translation behavior from numerical qualification and preserves a historical parity triage without changing any historical verdict to PASS. It does not claim that all SBML is supported.

## What the implementation represents

The modern importer is a conditional lowering from SBML core into BNGL. Parsing, conversion, structural round-trip, and simulation agreement are separate claims. A syntactically valid BNGL artifact does not establish that the source semantics were preserved, and a structural round-trip is not a biological correctness test.

| SBML surface | Current implementation boundary | Required evidence before claiming support |
| --- | --- | --- |
| Core Level and Version | The parser retains Level/Version and uses them for version-dependent rules. This is not a claim that every Core construct or every Level/Version combination is supported. | Valid-source checks plus construct-specific behavior tests and official/independent comparisons. |
| MathML | A defined subset lowers to BNGL expressions. Unsupported operators/functions and values outside the finite BNG3 value domain must refuse conversion. In particular, delay semantics are not represented by a parser-only expression rewrite. | Operator-specific tests; independent execution of the source law. |
| Units and coordinates | Unit definitions, model/species/compartment units, substance amount/concentration coordinates, and conversion factors are parsed and used in selected lowering paths. Dimensional consistency and every SBML unit combination are not thereby qualified. | Explicit amount/concentration, compartment-size, conversion-factor, and unit-scale cases checked against libRoadRunner. |
| Reactions and stoichiometry | Constant representable stoichiometry can lower. Variable, fractional, or otherwise nonrepresentable stoichiometry is conditional and must not be silently rounded or frozen. | Static and dynamic stoichiometry boundary cases plus source-coordinate trajectory comparison. |
| Rules and initial assignments | Assignment/rate rules and initial assignments have explicit lowering paths. Algebraic rules are not applied as implicit constraints and are reported as dropped; a model depending on them is not supported. | Per-rule-type and dependency-order tests; source trajectory comparison. |
| Events | Only event forms the runtime can schedule and apply are representable. Trigger timing, priorities, delays, trigger-time values, and repeated/state-dependent triggers require separate semantics; unsupported forms must refuse. | Trigger, priority, delay, assignment, simultaneous-event, and state-trigger tests against an independent simulator. |
| Fast reactions | The importer attempts a fast-reaction reduction for the subset that can be represented. A remaining fast reaction without an exact reduction cannot be treated as an ordinary reaction and still called supported. | Exact reduction tests and independent trajectories; otherwise an explicit refusal. |
| Constraints | SBML constraints are parsed for detection but are not enforced during simulation. Models whose validity or behavior depends on them are not qualified. | Enforced constraint semantics or explicit unsupported classification. |
| `comp` | Local/simple composition can flatten; other composition uses libSBML flattening with abort-on-unflattenable behavior and source-relative external-model resolution. Flattening success must be verified; a retained hierarchy is not imported as if exact. | Inline/external submodel tests, including unresolved and mixed-package failure controls. |
| `multi` | A bounded subset of Multi molecular types, complexes, seed patterns, species mappings, aliases, reaction mappings, compartment references, and numeric values is parsed. This is not blanket Multi support. | Construct-by-construct executable cases and structural plus trajectory checks. |
| `fbc`, `qual`, `spatial`, `arrays`, `distrib`, `dyn` | Package content that adds flux balance, logical transitions, geometry/diffusion, arrays, distributions, or dynamic-agent behavior is not imported as core kinetics. These constructs require explicit refusal when they affect model behavior. | Package fixtures proving fail-closed behavior, with annotation-only/empty-package controls. |
| `layout`, `render`, `groups`, `req` and annotation namespaces | Diagram or grouping metadata can be omitted when it does not change the mathematical model. Annotation-only namespaces are treated as metadata. | Verify mathematical model preservation and avoid claiming package round-trip preservation. |
| Unknown packages | Structural elements outside core annotation/notes containers are detected and reported as missing structure; an annotation-only namespace is not treated as a dynamic package. | Required/optional package controls and explicit warning/refusal behavior. |

The implementation also records finite-value, non-finite-value, spatial-dimension, and missing-rate limitations. Those are support boundaries only when the source is valid and the conversion refuses instead of substituting a materially different model. A source-invalid case must be validated before scoring conversion refusal.

## Historical failures requiring careful interpretation

The four `oscSystem` trajectory rows disagree with pinned BNG2 because the canonical BNG2 implementation explicitly marks network-simulation `TotalRate` as unimplemented (`legacy/perl/Perl2/RxnRule.pm:27-28`); `RateLaw.pm:25-26` defines the modifier as a total reaction rate. The exact source, SHA-256 `a86ce0ba68c0d4ccfda65d5b03bc29ed4ac1694dcc25028f2042a31a8698bb67`, declares two DNA copies and `DNA() -> DNA() + mRNA(loc~NUCLEUS) kTranscription*BooleanFunction() TotalRate` (`models/oscillatory_system/oscSystem.bngl:72,91,105`). For the full-flux law, the independently integrated source ODE gives 180.919243934 at 0.02, matching BNG3's 180.919243929. Multiplying the same flux by two DNA copies gives 361.838487868, matching BNG2's 361.838487736. This is a pinned-oracle capability gap, not evidence for changing BNG3 semantics. The old FAIL statuses remain visible, and an exact current-main replay receipt is still required.

The historical triage also identifies symbolic NET initial amounts that reload as zero in the `test_partial_dynamical_scaling` and `nfkb_illustrating_protocols` pathways. A current-source `test_partial_dynamical_scaling` replay confirms the native NET consumer defect; the `nfkb_illustrating_protocols` current replay remains pending. Both are separate from Atomizer lowering. The current-source `hybrid_test_hpp` parser failure on valid BNG2 observable syntax is likewise a parser compatibility defect, not proof of broad Atomizer scope. These are product defects and remain open until their focused repair and current-main verification are complete.

## Taxonomy defects in the generated limitation report

The stale expectation manifest currently labels `semantic/00951`, `stochastic/00028`, and `stochastic/00032` as atomizer-side `other` without a cause. Source and report evidence show different owners:

- `semantic/00951` is a valid SBML `<infinity>` constant beyond BNG3's finite value domain; it belongs under the existing `mathml:infinity` boundary.
- `stochastic/00028` and `stochastic/00032` convert, round-trip, and pass the independent comparison. Their official-reference limitation is random event-order/phase-boundary sampling, so the gap belongs to a harness/reference-comparability category, not an Atomizer refusal.

The generated document should be regenerated from refreshed exact-head measurements before those historical counts or labels are replaced. Until then, `other` is an identified manifest/doc taxonomy defect rather than an unexplained semantic failure.

## Completion criteria

This audit does not declare Atomizer completion. Completion requires a current-head full official suite and curated BioModels campaign with pinned source/native identities; all source models validated before product scoring; every non-pass assigned to exactly one primary cause with linked dependencies; current replays for defects and unresolved failures; explicit refusals for unsupported constructs; and no dynamic package or Core feature silently dropped. Independent SBML execution, structural round-trip, and any BNG2 compatibility comparison must remain separately labeled. Historical results, current queued jobs, and parser-level tests cannot substitute for those receipts.
