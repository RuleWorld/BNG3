# Tier-P direct NFsim path sweep

- Date: 2026-09-29
- Corpus: the committed tier-P selection, `provenance/corpus/selection.json` → `tiers.p`, **100 records** (all 100 on-disk `records` entries carry tier `p`)
- Sweep: `tests/validation/test_parity_nfsim.py::test_tierp_direct_path_outcome_is_measured_and_attributed`
- Per-model artifact: `build/validation/direct_path_sweep.json` (regenerated by every run)

## Reproduce

```sh
python3 -m pytest -c tests/validation/pytest.ini \
  tests/validation/test_parity_nfsim.py -k tierp -s
```

Roughly 90 s wall with `BNG_SWEEP_WORKERS=8` (the default). The test passes. It found three real divergences when first run; they are
fixed and documented below.

## Decline reasons, grouped by cause

All 16 declines are attributed: 15 name one of the nine builder stages in
`cpp/nfsim/NFinput/NFinput_fromAst.cpp:5967-5996`, and 1 is refused earlier by
the capability gate at `:5931-5942` before any stage runs.

| Attributed stage | Count | Models |
| --- | --- | --- |
| `observables` | 6 | `CaOscillate_Func`, `CaOscillate_Sat`, `Repressilator`, `actin_simple`, `fceri_ji`, `fceri_ji_red` |
| `seed species` | 4 | `Haugh2b`, `SHP2_base_model`, `nfkb_illustrating_protocols`, `univ_synth` |
| `functions` | 2 | `test_tfun`, `test_tfun_file` |
| `parameters` | 1 | `test_mratio` |

| `seed species` (threw) | 1 | `toy-jim` — `cannot find molecule type name 'Null' in System: 'model'` |

The 15 stage-attributed declines share one message shape,
`stage '<name>' could not be constructed directly (see preceding [nfsim/*]
diagnostics for the specific construct)`. The stage is attributed; the
*specific* construct is not, and the harness does not capture the `[nfsim/*]`
stderr that would say which. Distinguishing "observables declined for reason A"
from "reason B" is therefore not possible from this sweep.

## The 3 divergences: found, diagnosed, fixed

`AN`, `ANx`, and `ANx_noActivity` were accepted by the direct path and
disagreed with in-memory-XML at `rtol=atol=0`. **They no longer diverge.** The
cause was in the seed builder, not in observable binding:

`cpp/nfsim/NFinput/NFinput_fromCompiled.cpp:875` passed
`PatternStateConstraint::exact->index` to `Molecule::setComponentState` as the
NFsim state value. That index is an offset into the atomizer's *discovery order*
of allowed states (`cpp/compile/PatternDescriptor.cpp:467-469`), while every
molecule-type builder renumbers an all-integer site to `0..max`
(`addMoleculeTypesFromCompiled:590-593`, matching the XML loader at
`NFinput.cpp:585-591`). The two index spaces coincide only when a model happens
to declare its integer states in ascending order. `ANx` names `m~2` in its
species block before any observable names `m~0`, so `'2'` is discovery index 0
and every seed receptor was built in NFsim state 0.

The fix resolves the state id back to its name and asks the live `MoleculeType`
for the value, mirroring the product path. It was the only positional consumer
of that index in `cpp/nfsim`.

Two corrections to the first report of this, both verified since:

- the direct leg did **not** report the unmethylated count under `R0`. The
  observables were bound correctly all along; they faithfully reported a
  wrongly-built population. `RDtot` was 6660 in both legs, while `R0` was 6660
  direct and 0 via XML, and `R2` was 0 direct and 6648 via XML. The unmethylated
  count is 0 in both legs.
- the series were **not** permuted. `RD_R`/`RD_B` differ in their last digits
  (437/418 direct against 429/426 via XML), which a relabelling cannot produce —
  `MethLevel` reads the same wrong state, so the dynamics differ too.

The order dependence was measured directly. With `A(s~2) 100`, the direct path
reported `O2 = 0` when the species block came first and `O2 = 100` when the
observables block came first. Identical semantics, two different answers decided
by a detail with no semantic content; the XML leg was invariant throughout.

This is exactly the class of defect the parity gate exists to catch, and it was
invisible to any test that compares a model against itself on a single route.

The sweep now reports **0 diverged**, and the strict-xfail marker that was
holding the three models is cleared. It is kept as an explicit empty tuple so a
recurrence has somewhere to be named and so a model that starts diverging again
fails rather than being absorbed into a pass.

## What was deliberately not counted

- **18 "no comparable observables"** (`blbr`, `fceri_*`, `test_paramname`,
  `statfactor`, …): both legs return an empty observable set, so
  `compare_trajectories` reports `max_rel_err=inf` with no offending column.
  That is a harness limitation — there is no trajectory to compare — and is
  reported as its own bucket rather than as a divergence. The 18 models are
  accepted but **unverified**.
- **6 "parity leg unavailable"**: the direct leg ran, the forced-XML leg raised.
  5 are `Failed to initialize NFSim system from model XML`; `isingspin_localfcn`
  is `dynamic rate argument 'z' has no scoped reactant`. These are XML-path
  failures, not direct-path evidence.
- **4 "not loadable"**: `actin_branch`, `actin_branch_forFitToData`,
  `hybrid_test_hpp`, `push_pull` fail BNGL parsing. They never reach the
  builder, so the direct path is not what turned them down.
- **2 "incomplete"**: `Motivating_example` and `test_fixed` abort the process
  via `exit(1)` from `cpp/nfsim/NFcore/reactionClass.cpp:175` and the NFsim
  `Trash` guard respectively. They would otherwise be classified. Each model is
  probed in a child process so these aborts cannot take pytest down.

## Scope of the sample — stated plainly

This is the **complete committed tier-P selection, all 100 records**, not a
sample. The task brief described it as "roughly a thousand records"; the
committed manifest holds 100, and all 100 were attempted.

Two deliberate bounds, both in the *harness*, neither reducing coverage:

1. **Horizon `t_end=0.1, n_steps=10`, seed 7**, versus the `t_end=50,
   n_steps=50` the tier-NF comparison uses. Acceptance is decided by the nine
   builder stages, all of which run before the first time step, so a short
   window measures the property being counted. Cost is the reason: `egfr_net`
   alone needs 108 s at `t_end=50`, and `blbr` needs 42 s even at `t_end=0.1`.
   The `t_end=50` tier-NF comparison is unchanged.
   **Consequence:** a model that diverges only late in a trajectory would be
   recorded as clean here.
2. **300 s per-model timeout.** No model hit it; the slowest, `blbr`, took
   ~42 s.

## What this number establishes

- The direct NFsim path accepts **78 of the 100 committed tier-P models**, and
  every refusal names either a builder stage or the capability gate. The
  fail-closed attribution contract in `NFinput_fromAst.cpp:5908-5918` holds
  across the whole selection.
- Declines are **not broad**: 78% acceptance, concentrated in five stages,
  with `observables` and `seed species` accounting for 10 of 16.
- **It is not parity.** 3 accepted models are observably wrong, and 18 more are
  unverifiable. ADR 0001's gate is not met, and the reason is now a number
  rather than an assumption.

## What it does not establish

- Nothing about numerical *accuracy*. This compares the two construction routes
  against each other; it never invokes the native NFsim oracle. Two paths can
  agree and both be wrong.
- Nothing outside tier-P. The BioModels and SBML suites are not swept.
- Nothing about long-horizon behaviour (bound 1 above).
- Nothing about the 18 incomparable and 6 parity-unavailable models. They are
  accepted, not verified.

## Consequences for ADR 0001

The "full parity matrix" the ADR defers to now exists and is not green. The
blocking items are narrow and specific: the `AN`-family observable-binding
defect, and the `observables` / `seed species` builder gaps. Fixing any of them
is out of scope here — this sweep measures, it does not repair.
