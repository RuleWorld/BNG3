# BNGsim migration status — lowering coverage & gap classification

> This is the live inventory for ADR 0003. It enumerates every current
> `BNGsim adapter rejected` branch, classifies each gap (Type A/B/C), and
> records the required fallback. It is test-backed: every row has a owning
> test or a `TODO` ticket.

**Last audited:** 2026-09-17
**Adapter source:** `cpp/engine/BngsimAdapter.cpp`
**Pinned BNGsim:** `49dc939035f5a272da663f8c9586e3c9f0e1c041` (see `provenance/upstreams.lock.yml`)
**Default backend:** `native` (auto-select prefers `bngsim` only when faithfully lowerable)

## How to read

- **Type A — BNG3 lowering gap:** BNGsim already has enough representation; fix BNG3 adapter.
- **Type B — BNGsim capability gap:** BNGsim's public finite-network API cannot represent the behavior; keep fallback, document blocker, optionally file upstream issue for `lanl/bngsim`.
- **Type C — inherently rule-level / network-free semantics:** should be resolved before the boundary (effective finite rates generated by BNG3 rule/network generation; network-free-only constructs remain on NFsim).

Rejection is **fail-closed**: the adapter throws before solver construction with
`BNGsim adapter rejected …: …` rather than silently producing a changed model.

## Migration phases (per ADR 0003)

- **Phase A (this doc):** architecture explicit, inventory complete, no behavior change required, tests still pass.
- **Phase B (harden lowering):** reduce `ast::Model` coupling, use `CompiledModel` where available, classify every rejection, expand Type-A gaps, keep fail-closed.
- **Phase C (ODE backend):** ODE dispatch to BNGsim behind opt-in, result conversion, native-vs-BNGsim differential tests.
- **Phase D (preferred ODE):** prefer BNGsim for supported finite ODE models with visible fallback.
- **Phase E (SSA):** BNGsim SSA dispatch with seeded-reproducibility and distributional checks.
- **Phase F (higher-level):** scans, steady state, sensitivities, numerical events, PSA where equivalent — all via BNGsim where supported.
- **Phase G (cleanup):** decide native fallback vs retirement only after parity evidence.

## What this doc does not claim

- It does not claim compartments, energy/barrier/driven semantics, or population
  maps are representable in BNGsim today.
- It does not claim relative TFUN or non-reference rates are already bridged.
- It does not change `method="nf"` routing.
