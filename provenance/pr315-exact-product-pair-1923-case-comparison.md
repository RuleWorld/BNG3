# PR #315 replacement-pair conformance evidence

The exact replacement runs establish a product-revision difference under one modern harness. The base product at `ba892814cea8b2d48a9c2304ebbfb8771a5e0f43` and merge product at `25f13c5bf9924dd413ab659198095b5d8d6bee05` were both built and tested with harness revision `18ccc087226018e6eb4ec6d80db30454e4ef4c2b`, Python hash seed `0`, and the same clean SBML Test Suite commit and source-lock hash. Each run retained all 1,923 case records.

The pair comparison found 63 core pass-to-fail changes: 62 cases moved from official-reference pass to fail, and one moved from official-reference unsupported to fail. The generated BNGL and SBML artifacts were byte-identical across all 1,923 cases. The 63 changed cases have identical SBML, settings, and results input hashes across the base and merge runs and the recovery report. Four shared timeouts (`semantic/01561`, `01562`, `01563`, and `01565`) are outside the changed-verdict cohort. `stochastic/00003` failed its official statistical check in both replacement runs; the distinct `semantic/00003` case passed in both.

At the exact PR #389 merge `31ae76c19fdd03c9d4af788f58dd5187726e14a1`, the complete report shows all 63 affected cases passing the core gate. Official-reference outcomes are 62 passed and one unsupported: `stochastic/00032` is classified unsupported because the official output grid includes an event phase boundary where the reference convention and the native action-dispatcher convention differ. The case is not counted as a failure.

The case IDs match the 63 IDs in the earlier PR #315 provenance report. That earlier run is explicitly invalid because it loaded the shared primary native extension, so the ID match is historical context only; it does not validate that run or its artifacts. The original PR #315 base/merge runs also lacked case reports and failed harness-contract checks before conformance execution.

This evidence attributes the observed changes to the exact product revisions under a pinned harness and shows recovery at the PR #389 merge. It does not isolate a single source hunk as the cause. The JSON companion records run identities, artifact/report hashes, per-case recovery status, input hashes, and report-record hashes. The full 67.7 MB artifact diff remains outside the repository under `/tmp/bng3-campaign/replacement-pair-diff-validated.json`.
