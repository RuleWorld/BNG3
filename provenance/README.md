## SBML Atomizer coverage campaign

[`sbml-campaign/`](sbml-campaign/) holds the machine-readable records of the
SBML Atomizer coverage campaign. The
[expectation manifest](sbml-campaign/README.md) records the expected verdict
of every official SBML Test Suite case at every stage of the gate, so a
coverage regression fails a comparison instead of needing a human to read two
large reports side by side. Every record there is regenerated by a command
documented in that directory's README.

## Curated BioModels corpus

[`curated-biomodels-corpus-inventory.json`](curated-biomodels-corpus-inventory.json)
records one measurement of the curated BioModels corpus (`curationstatus:Manually
curated`, snapshot 2026-09-15, 1096 records of which 1083 reach the SBML
path): which records exist, what the Atomizer did with each of them in the
flat and the atomized mode, and the classification of every residual failure
and timeout.

[`curated-biomodels-corpus-expectations.json`](curated-biomodels-corpus-expectations.json)
is the corpus's **expectation manifest**: the expected verdict of every
curated record at every stage of the corpus gate, so a corpus regression
fails a comparison instead of needing a human to read two large reports side
by side. It uses the vocabulary of the
[SBML campaign manifest](sbml-campaign/README.md) so the campaign has one
vocabulary rather than two, and its schema, its regeneration command and its
comparison semantics are documented in
[`docs/CURATED_BIOMODELS_CORPUS.md`](../docs/CURATED_BIOMODELS_CORPUS.md).

[`scripts/ci/compare_biomodels_suite_reports.py`](../scripts/ci/compare_biomodels_suite_reports.py)
compares two corpus reports with each other, for the same purpose as
[`compare_sbml_suite_reports.py`](../scripts/ci/compare_sbml_suite_reports.py)
does for the official suite: it reports verdicts rather than provenance, it
compares the aggregate id lists as multisets so a reordered run is not a
difference, and it keeps a timeout-only difference distinct from a real
change.

## Golden bundles
Provenance-complete golden bundles use the schema in
`schemas/golden-manifest.schema.json`. Validate a candidate or approved bundle
with:

```bash
python scripts/validate_golden_manifest.py \
  --manifest provenance/golden/<bundle>/manifest.json
```

The validator checks every referenced byte and rejects an `approved` bundle
until the source lock, oracle artifacts, and immutable compiler images are
actually locked.

## Reconciliation ledgers

Create one ledger per reconciliation source under `provenance/reconciliation/`
and validate it explicitly:

```bash
python scripts/validate_provenance.py \
  --ledger provenance/reconciliation/bionetgen.yml
```

Each ledger must conform to
`schemas/reconciliation-ledger.schema.json`. The source's represented revision,
chosen cutoff, and owner are required; each source commit then receives exactly
one classification, rationale, reviewer, and test list. Do not create an empty
ledger with guessed revisions or owners merely to satisfy the shape.
